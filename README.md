# トレカ価格自動追跡ツール

1日3回（JST 13:00 / 15:00 / 18:00）GitHub Actions が自動で動き、次の2つを記録します。

1. **BOX価格トラッカー**（本命）: BOXの買取の**出現・消滅**を検知し、価格推移を公開ページに表示する
2. **カード価格の収集**: PRICE BASE のワンピースカード買取表から、指定キャラ（ルフィ・ゾロ・ナミ・ハンコック）のカード価格を記録する

## 今すぐ更新したいとき

GitHub のリポジトリ → **Actions** タブ → 左の「買取価格の収集」 → 右の **Run workflow** → 緑の **Run workflow**。
1〜3分で終わります。実行画面の下部（Summary）に件数と、出現・消滅・要確認の一覧が出ます。赤（失敗）の場合は、サイトの作りが変わった可能性があります（そのとき既存データは壊れません）。

## 公開ページ（GitHub Pages）

初回だけ設定が必要です: リポジトリの **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main` / フォルダ `/docs` → Save**。
数分後に `https://po-one-tcg.github.io/card-price-tracker/` で見られます（スマホ対応）。

- ホーム: 直近30日の出現・消滅の一覧、ゲーム一覧
- ゲームの価格表: 店舗が横に並ぶ表（店舗名の行は固定）。🆕出現 / ✕取扱終了 を強調表示
- 商品ページ: 価格推移グラフ、前日・1週間・2週間・1ヶ月・3ヶ月・半年の差額と変化率
- 値動きランキング: 期間ごとに、いま一番動いている商品

## BOXトラッカーの判定ルール

店舗×商品ごとに、前回と今回を比べます。

| 前回 → 今回 | 扱い |
|---|---|
| 取扱なし → 金額あり | **出現**。すぐ公開に反映 |
| 金額あり → 取扱なし | **消滅**。すぐ公開に反映 |
| 金額あり → 金額あり | 変化率が **±50%超**（0円・桁間違いを含む）なら**保留**（公開は前の価格のまま）。それ以下は通常反映 |
| 金額が確認できない（「買取中！」「価格更新中」） | **未確認**。前日の価格は引き継がず、検知にも使わない |

- **取得失敗は「消滅」にしません。** ページが取得できない／構造が変わって0件／商品数が前回の6割未満に急減、のときはその回を丸ごと無効にして、データを変えません（実行ログに失敗として残ります）。
- 直近の成功から30時間以上たった店舗は、公開ページで価格を出さず「未確認（最終更新 n日前）」と表示します。
- 各店舗の**初回**の巡回は基準データづくりで、出現・消滅は判定しません。

### 保留（要確認）の項目を処理する — 管理画面

`https://po-one-tcg.github.io/card-price-tracker/admin/` を開きます（公開ページからはリンクしていません）。

- **最初の1回だけ**: 画面の案内どおりにGitHubのトークン（このリポジトリの Contents と Actions を Read and write にしたもの）を作って貼り付けます。トークンはそのブラウザの中にだけ保存され、リポジトリには入りません。
- 要確認の項目ごとに「**正しい**」「**間違い → この価格に修正**」「**間違い → 前の価格のまま**」を押します。
- 判断は次の更新の最初に自動で反映されます。すぐ反映したいときは画面下の「今すぐ更新を実行」を押します。

コマンドで行う場合（管理画面と同じ結果になります）。保留中の一覧を見る:

```
node scripts/box/review.js list
```

判断を記録（次回の収集の最初に反映されます）:

```
node scripts/box/review.js approve  <商品名の一部>          # 正しい → 公開に反映
node scripts/box/review.js set      <商品名の一部> <価格>   # 間違い → 正しい価格に修正して反映
node scripts/box/review.js dismiss  <商品名の一部>          # 間違い → 前の価格のまま据え置き
```

`set` / `dismiss` の後、サイトが同じ誤った値を出し続けても、再び保留にはなりません。

## 買取EXPOの取り込み（管理画面で毎日）

買取EXPOはXのポストが情報源なので、管理画面 `.../admin/` の「② 買取EXPOの入力」に**ポストを貼り付けて**取り込みます。

1. Xでその日のポストをコピーし、入力欄にそのまま貼り付けます（複数本まとめてOK。「✅」で始まる見出しごとに自動で分けます）。
2. 「読み取る」を押すと、区分ごとに件数と、**確定したらどうなるか**（🆕出現・✕消滅・⚠要確認になる商品）が表示されます。
3. 内容を確認して「この内容で確定して取り込む」を押します。「取り込み後すぐ更新を実行する」にチェックがあれば、1〜3分で公開ページに反映されます。

- 各区分（ポケカ BOX、ワンピース BOX・カートンなど）の入力状況が ✅/⚠ で並びます。**⚠ の区分は、入力しないと公開ページで「未確認」**になります（36時間）。
- **貼り忘れ対策**: 前回の6割未満しか貼られていない区分は、確認のチェックを入れるまで取り込めません（貼り忘れると、載っていない商品が全部「消滅」に見えてしまうため）。
- **価格変更のお知らせ**（「下記商品の買取価格を只今より変更…」）も、そのまま貼れます。書かれた商品の価格だけが更新されます。
- **「買取EXPO 本日休止」ボタン**: 全商品が「休止」表示になります。休止は**出現・消滅にはカウントしません**（1日休むだけで全商品が「消滅」→翌日「出現」になり、通知が埋まるため）。〆切だけが消滅です。
- `シュリ無` = シュリンク無し（付いていなければシュリンク付き）、`(カートン)` = カートン、`〆切` = 買取停止として読み取ります。
- 見出しが未対応（新しいジャンルなど）のときは、プレビューで「当てはまる区分」を選べます。恒久的に対応するには `config/box-targets.json` の `expo` の `sections` に見出しを書き足します。
- ポケカのシングル買取レート（レアリティ別の表）と、ワンピースの「バラパック」「パラレル」のレートは、BOXの価格ではないので**取り込みません**（`sections` の `kind: "skip"` / `excludeContains`）。
- 同じ商品は、名前の表記ゆれ（全角半角・空白・末尾の「BOX」など）を無視して PRICE BASE の商品と自動で結び付けます。結び付かないときは別の商品として登録されます。

## 買取コレクトの取り込み（価格表の画像）

買取コレクトは、価格表の**画像**（スプレッドシートのスクショ）と、価格更新の文章ポストが情報源です。画像はAIが読み取って、EXPOと同じ書式の文章にし、管理画面に貼ります。

1. 買取コレクトの新しい画像を、Claude（このチャット）に貼って「コレクトの画像を取り込み用に書き起こして」と頼みます。
2. Claudeが出した文章（`✅コレクト ポケカ BOX` などの見出しつき）を、管理画面の入力欄に貼って、EXPOと同じ手順で確定します。
3. 文章の価格更新ポスト（「買取価格を更新しました！」など）は、内容を `✅コレクト 価格変更` の見出しに、`商品名 金額円` の行にして貼ります（同じくClaudeに頼めます）。

- 書式の見本は `scripts/box/fixtures/collect-2026-09-19.txt`（画像の全商品）と `collect-update.txt`（価格変更）です。
- 表の `-` は「買取なし」で、〆切として扱います。ポケカBOXは、シュリンクつき／なしの2列を、商品名に `シュリ無` を付けた行に分けます。
- コレクトは更新が不定期なので、入力しなくても**7日間**は「未確認」にしません（`config/box-targets.json` の `freshHours`）。
- ポケカのシングル買取レート（AR/CHR ¥160 など）は取り込みません。
- ワンピース・ドラゴンボールは、名前が店ごとに違っても、型番（OP-01、FB02 など）で同じ商品として結び付けます。

## RUNTO（自動取得）

RUNTO（runto666.com）は、ネットショップの公開API（WooCommerce の Store API）から、**1日3回自動で**取得します（手入力は要りません）。APIは1回の取得で4回ほどです。

- ポケモン・ワンピース・遊戯王・ドラゴンボールの4カテゴリを取得します。
- 商品ごとに、**状態別**（シュリンク有/無・カートン・テープカット・パック・白箱）の価格を持ちます。ポケモン以外は、「シュリンク有」を通常の未開封BOX（`box`）として扱います。
- **在庫なし = 買取停止**（EXPOの「〆切」と同じ）です。在庫なし→ありで出現、あり→なしで消滅になります。
- 取得できなかったとき・件数が急減したときは、その回を無効にします（誤って消滅にしません）。
- 商品名は、他のお店と同じ商品として結び付けるために整えています（`scripts/sites/runto.js`）。結び付かないものは `config/product-aliases.json` に書き足します。

## BOXの並び順（発売日の新しい順）

ゲームの価格表は、**区分の中で発売日が新しい順**に並びます（商品名の下に発売日を表示）。区分の順番も、新しいシリーズが上です（ポケモンなら MEGA → SV → ソード&シールド → サン&ムーン → …）。発売日が分からない商品（特別セット類など）は、区分の最後に並びます。

- 発売日の表は `config/release-dates.json` です。**ポケモン**は、参考ページ（https://learn-book.com/pokemon-rekidai-pack/）から自動で取り込みます。**ワンピース**は、手で書いてあります（型番 OP-01 などで一致するので、店ごとに名前が違っても大丈夫です）。
- **新しい弾が出たら**、次を実行して発売日を更新します（または Claude に「発売日を更新して」と頼みます）。
  ```
  npm run update:release
  ```
  ワンピースなど他のゲームは、`config/release-dates.json` に発売日を書き足します。
- 店ごとに商品名の表記が違って発売日が引けないものは、同じファイルの `aliases`（別名の対応表）に「店の表記 → 発売日の表の名前」を足します。
- 区分の並び順は `config/box-targets.json` の `games[].groupOrder` です。

## 保存されるデータ

```
data/box/state.json           店舗×商品ごとの現在の状態（確定済み価格・保留中・直近の出現/消滅）
data/box/products.json        商品の一覧（名前・区分・画像）
data/box/history/日付.jsonl   公開状態が変わったときだけ記録する履歴
data/box/runs.jsonl           巡回の成功/失敗ログ（日次の推移の復元に使う）
data/box/events.jsonl         出現・消滅・保留などのイベント記録
data/box/decisions.json       管理者の判断（保留の処理）
data/box/manual/inbox/        管理画面から届いた買取EXPOの取り込みデータ（次の更新で処理される）
data/box/manual/done/         処理済みの取り込みデータ（結果つき。60日で削除）
backups/                      更新の直前に自動で取る日付つきバックアップ（直近7日は全部、以降は1日1つ、90日で削除）
docs/                         公開ページ本体（docs/data/box.json は自動生成、docs/img/box/ は商品画像）

data/history/日付.jsonl       カード価格の全取得結果（追記式）
data/cards.json               カードの一覧、data/images/ にカード画像（初出のときだけ保存）
```

## 対象を増やす

- **BOXの店舗・ゲーム**: `config/box-targets.json` の `stores` に書き足します（`scripts/sites/pricebase.js` が見本のパーサー）。同じ店舗に `sources` を足せばゲームを増やせます。
- **カードのキャラ**: `config/targets.json` の `characters` に1行足します。拾いすぎたカードは `exclude` に名前の一部を入れて除外します。
